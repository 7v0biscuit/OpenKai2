# v0.1.10

This release addresses the impact-effect dispatch stop after an attack and
removes repeated setup and transfer work from vector execution.

- Register the complete impact lifecycle tables, including the constructor at
  `0x210c00`. Check 112 original factory cases across all seven impact types,
  allocation failure, actor parameters, resources, and saved registers.
- Reuse decoded vector instructions during each execute/resume call and
  decode only changed words after an upload. Retain instruction-boundary
  invalidation when a host callback updates code.
- Reset XGKICK transfer metadata without clearing its entire 64 KiB packet
  buffer. Preserve cycle-by-cycle reads and wraparound with contiguous qword
  copies. Walk sparse register masks directly during hazard checks.
- Avoid repeated MinGW CPU-capability probes when switching vector rounding
  modes. Check 128 host rounding and exception-flag combinations.
- Add 40 vector conformance cases and 64 original interpreter references for
  registers, flags, cycles, memory, and packet bytes.
- Record whole guest, DMA, and vector execution timings under `[runtime:work]`
  so logs can distinguish those costs from rasterization.

Three-run native Linux kernel measurements reduced vector arithmetic time by
about 12%, a 4 KiB XGKICK workload by 16%, short launches by 54%, and repeated
code-upload work by 81%. Windows-under-Wine results also improved, with larger
reductions where the repeated CPU probes were expensive. All sixteen workloads
retain matching guest cycles and state/packet checksums. These are synthetic
kernel measurements, not retail game FPS results.

Host audio remains disabled. The original USA ISO is required at every launch.
Complete retail attack sequences, uninterrupted matches, and sustained 60 FPS
remain unverified.
