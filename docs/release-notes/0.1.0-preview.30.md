This preview addresses missed confirmation input at low frame rates and reduces
CPU work in the translated game and software renderer. Preview 29 reaches the
title screen, but retail testing stops at the create-save confirmation and reports
about 2 FPS on an supported CPU with an supported GPU.

Keyboard and controller input is now sampled on the window thread. Short presses
remain pending until the game reads them, so a tap is retained even if released
between slow frames. Held buttons, releases, analog positions, and separate
controller ports are tested. Use **X or Space (Cross)** to confirm a highlighted
choice; Enter maps to Start.

Normal translated game routines now compile with optimization enabled. One
oversized unit remains unoptimized to bound compiler resource use. The renderer
also hoists common opaque sprite state and avoids redundant bilinear reads when
all taps share a cache page. Complete VRAM comparisons against the previous
scalar renderer cover 64 textured and solid sprite cases, including fallback
modes, depth, blending, masks, fog, filtering, and texture feedback.

The isolated aligned 512x448 bilinear sprite benchmark takes about 7.9 ms of CPU
time per draw, down from 14.0 ms on the development host. This is not a retail
FPS measurement. The renderer still runs on the CPU, and stable 60 FPS is not
verified.

A new save regression executes the original game directory and file callbacks,
checks the actual saved bytes, restarts the memory-card SDK, and reads those bytes
back into guarded guest memory. It uses an isolated temporary save directory.
Startup logs now include bounded save-command and controller snapshots to help
diagnose remaining prompt or storage failures.

The original USA ISO is required at every launch. The updated retail save flow,
gameplay, audio synchronization, and frame rate still need end-to-end validation.
