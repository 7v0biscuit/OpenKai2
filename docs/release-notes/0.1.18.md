# v0.1.18

Reduce GPU submission overhead and unnecessary VRAM readbacks.

- Reuse texture source-page footprints while addressing state is unchanged.
  Compute aligned buffer coverage directly from logical page ranges, retaining
  the previous addressing walk for unaligned bases and wrapped memory.
- Skip depth-page preparation when a draw neither reads nor writes depth.
- Read back only the dirty pages needed by pixel accesses, partial texture
  uploads, and palette loads. Preserve unrelated GPU data and retain full
  synchronization for presentation, snapshots, resets, software fallbacks,
  and local transfers.
- Compare 8,320 page masks with the previous renderer. Check 128 draws that
  change texture addressing, plus four single-page readback cases followed by
  complete VRAM comparisons. Retain the existing GPU and vector references.
- Add optional page-preparation and small-draw submission benchmarks to
  `openkai2_gpu_bench`; both preserve reference checks and output hashes.

Three alternating Windows-binary runs under Wine with Mesa measured 42–48%
lower costs in four small textured draw batches, including GPU completion.
Complete VRAM matched the CPU renderer and all before/after output hashes
matched. These synthetic submission costs are not estimates of hardware game
FPS or sustained 60 FPS.

The original USA ISO remains required at launch. Host audio remains disabled.
Complete matches and sustained 60 FPS remain unverified. Synthetic benchmark
costs do not establish hardware game performance.
