# v0.1.21

Reduce vector code-upload overhead and correct packed vertex texture and depth
state.

- Validate the fetched instruction pair instead of scanning an entire decoded
  vector program after each microcode write. Preserve code edits from callbacks,
  sliced execution, program identity changes, and the original instruction
  cycles. Add 64 state, cycle and data snapshots from the pinned interpreter
  across both vector units, unchanged uploads, executed/unused edits, and resume
  boundaries.
- Keep GIF's temporary Q separate from the perspective value latched by RGBA.
  STQ writes update the temporary; RGBA latches it into vertex state. Tag
  boundaries reset the temporary while retaining the previous vertex Q. Direct
  and REGLIST RGBAQ writes keep their explicit Q.
- Preserve every bit of packed XYZ2/XYZ3 depths instead of rounding them through
  float32. Exercise both packet parsers, register ordering, chained tags, reset,
  and large integer depths against independent expected values.
- Record vector code-generation counters on shutdown to help distinguish code
  uploads from instruction execution costs.

Three alternating Windows-binary runs under Wine measured 17–47% lower CPU
cost in twelve short-program code-update cases. Two existing VIF MPG upload
workloads improved by about 55–56%. General and product controls had approximately
0.5% and 1.8% higher median costs, respectively. Output state, cycle and packet hashes matched.
These synthetic measurements do not establish retail game FPS.

The original USA ISO remains required at launch. Host audio remains disabled.
The packet corrections still need retail validation for character appearance;
complete matches, correct poses, and sustained 60 game FPS remain unverified.
The display limit controls window updates and retains original guest timing.
