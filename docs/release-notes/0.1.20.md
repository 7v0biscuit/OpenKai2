# v0.1.20

Reduce vector flag-processing costs, add configurable display pacing, and
register the actor state command bank.

- Classify the selected product lanes together for vector multiply-add and
  multiply-subtract sticky flags. Preserve scalar handling for boundary
  products, underflow, overflow, and exceptional input normalization.
- Assemble MAC and STATUS flags from packed lane bytes while retaining
  destination masks, flag visibility, and instruction cycle boundaries.
- Set the host display limit to 240 FPS by default. Accept `--fps-limit=1..240`
  or `--fps-limit=0` for unlimited output. `OPENKAI2_FPS_LIMIT` applies to
  extracted, portable, and installed launches; a command-line value overrides
  the environment setting. Invalid limits are rejected.
- Keep guest clocks, simulation, movies, and vector scheduling at their original
  rates. Repeated window requests reuse the latest available frame. A 240 Hz
  window does not establish 240 newly rendered game frames per second, and no
  frame interpolation is included.
- Register all thirteen methods in the actor state bank, including
  `0x001F9290`. Verify its bank, the complete bank catalog, method instructions,
  and generated dispatch. Add 72 state-query and 39 original caller cases,
  bringing actor-command regression coverage to 453 cases.

Three alternating Windows-binary runs under Wine measured 7–17% lower CPU cost
in eight multiply-add/subtract programs. The 32 selected-operand programs had
about 33% lower median cost, with individual reductions of 3–58%. The general
control group had about 0.8% higher median cost. All output state and cycle
hashes matched. These synthetic costs do not establish game FPS.

The original USA ISO remains required at launch. Host audio remains disabled.
Complete matches, character poses, and sustained 60 or 240 game FPS remain
unverified. Guest vector execution still limits game-frame generation.
