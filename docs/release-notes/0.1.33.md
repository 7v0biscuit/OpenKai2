# v0.1.33

Draw on a separate GS thread, stream music the way the SPU2 plays it, and
match PCSX2 for more vertex upload cases.

- Process GS packets on their own thread. In the last fight log, GS work took
  about 61% of the game thread's time; it now overlaps the game's own work.
  The game still sees the GS exactly as before: GS register reads, VRAM
  readbacks and each vertical blank wait for queued drawing to finish.
  Setting `OPENKAI2_GS_THREAD=0` restores single-threaded drawing.
- Encode GPU draws in place and reuse the previous draw's page footprint, and
  keep the GPU command buffer between batches. GIF processing takes about 40%
  fewer instructions per triangle in the submission benchmark.
- Stream AutoDMA music as the SPU2 plays it. Each music block used to be
  copied the moment its transfer started, so audio the sound driver wrote
  ahead of the read position during the transfer was never heard. While a
  transfer runs, its DMA channel now also reads busy and its address
  advances, as on the console.
- Fix unaligned word loads on the IOP. An LWL/LWR pair lost half of the word.
- Follow PCSX2 for VIF fill-mode unpacks and MODE 3, two more vertex upload
  cases that left wrong values in VU memory and could distort legs, belts
  and other accessories.
- Report the time the game waits on the GS (`stage=gs-fence`) and AutoDMA
  music transfers (`[audio:adma]`) in the startup log.

The original USA ISO is required. These changes are verified by unit, GPU
comparison and audio tests and need in-game confirmation.
