# v0.1.30

Fix character facing in story mode, give VU0 conversions console results, play game audio and cut VU1 overhead.

- Pass the game's double-precision `atan`, `floor` and `fabs` in integer
  registers, as the EE's libm does. The stubs read and wrote float registers,
  so `atan2` returned garbage and Dragon World characters turned toward the
  wrong point, walked off the board and soft-locked.
- Saturate VU0 `VFTOI` by sign, return the signed VU maximum from `VDIV` and
  `VRSQRT` by zero, and keep the `VRSQRT` numerator. Overflowing screen
  coordinates used to wrap to zero.
- Play streamed music, voices and movie audio through a 48 kHz, 32-bit float
  stereo stream at the SPU2's own rate, with both cores mixed under a soft
  limiter. Settings → Display → Game audio turns it off or sets the volume.
  Sound effects played through SPU2 voices are not synthesized yet.
- Run VU1 microprograms on the runtime's data memory in place. The bridge
  used to copy 16 KiB in and out on every program and around every XGKICK;
  the vector benchmark now executes 69% fewer instructions with identical
  results.
- Trim per-draw GPU submission work and let 16 GPU batches queue instead of
  4, so a slow batch no longer stalls the game thread.

The original USA ISO is required. The facing, VU0 and frame-rate changes are
checked by unit tests and benchmarks and need in-game confirmation in story
mode and fights. AMD FSR 3 and FSR 4 are not included: both need per-pixel
motion vectors and DirectX 12 or Vulkan, and FSR 4 runs only on Radeon RX 9000
GPUs. FSR 1 remains available under Upscaling.
