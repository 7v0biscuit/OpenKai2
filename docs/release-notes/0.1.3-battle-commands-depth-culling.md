Complete battle command registration and early depth rejection for hidden pixels.

## Changes

- Register all 24 handlers in the 45-slot battle command table, including `0x001C8900`. Verify both dispatcher switches, reserved entries, and complete handler instructions against the supported executable.
- Run the original dispatcher in 540 bounded regression cases covering enable flags, filtering, repeated model callbacks, character state, source parameters, saved registers, and stack guards.
- Reject hidden pixels before texture sampling on supported CT32 draws with immutable source pages. Preserve final texture-cache state through deferred samples.
- Probe depth coverage before enabling the optimization. Keep feedback, stale pages, alpha/destination tests, masks, fog, and other formats on their existing paths.
- Add 48 serial/parallel VRAM comparisons and report rejected-pixel counts in startup diagnostics.

The 18-fixture raster benchmark measured 22–46% lower draw times with approximately 50% depth rejection and 79–93% lower times with full rejection. Visible fixtures had at most about 4% overhead. Three-run medians retained identical VRAM hashes. These are synthetic draw measurements, not game-FPS results.

The optional `openkai2_depth_bench` CMake target is available for repeatable measurements.

## Status

The command entries address a reproduced stop during battle setup. Complete battle loading and stable 60 FPS remain unverified. The movie decoder and audio implementation are unchanged.

The original Budokai 2 USA ISO is required at every game launch. Game files are not included.
