This preview moves presentation off the window thread to address keyboard and
window stalls during slow software rendering. The Preview 30 report describes
an unresponsive create-save prompt. Its log contains no save write or exception;
it records ongoing game execution and a normal window-close request. Movie
playback averages about 13 FPS, so the 60 FPS target remains unmet.

Presentation requests now run on a worker. The window thread continues polling
input while the renderer waits for drawing or converts a framebuffer. Repeated
requests coalesce to the latest field instead of building a backlog. Shutdown
joins the worker, and worker errors return to the launcher. A regression blocks
presentation deliberately and checks that requests remain responsive, only the
latest pending field is rendered, and errors are reported.

Bilinear sampling now interpolates RGBA with SSE4.1 while retaining scalar
rounding. For disjoint CT32 texture and framebuffer ranges, stable texture reads
avoid repeated 8 KB page copies. The initial stale cache page, eviction order,
and final cached contents are preserved. Feedback, depth writes, other formats,
and wrapping memory retain the ordinary path. Validation includes 8,192 scalar
color comparisons, cache-state checks, and 64 complete VRAM comparisons.

The isolated 512x448 bilinear benchmark fell from 15.85 to 11.04 ms per draw for
fractional samples and from 7.68 to 5.69 ms for aligned samples on the development
host. These are CPU measurements of one drawing operation, not retail FPS.

Input validation now sends a released Cross tap through the game's compiled
pad-read entry and checks the actual guest packet, return, bounds, and separate
ports. Keyboard input also remains active when a controller is connected. Save
validation begins with the original 21-sample card detection and missing-directory
search, then checks directory creation, file callbacks, SDK restart, and readback.
It does not dismiss the in-game confirmation or create a substitute game save.

Logs identify the source revision and retain bounded save-state and input-delivery
records after the movie. Presentation records distinguish window frames, rendered
frames, and guest fields. They must not be interpreted as interchangeable FPS
measurements.

The original USA ISO is required at every launch. The updated retail prompt,
gameplay, audio synchronization, and stable 60 FPS still require verification.
