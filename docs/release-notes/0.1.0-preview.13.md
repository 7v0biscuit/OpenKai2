This preview restores the SDK thread initialization needed to create the game's
EE workers. The latest startup log preserves the main thread's return address
but shows it asleep with no worker threads available to wake it.

The SDK `InitThread` replacement previously returned success while leaving the
bootstrap thread at priority zero. The game copies that reported priority into
its worker descriptors, which `CreateThread` correctly rejects. Initialization
now moves the bootstrap thread to priority one, as the original SDK routine does.
Repeated initialization preserves a priority already configured by the game.

The regression checks priority inheritance, worker descriptors, invalid-priority
rejection, and saved registers. The packaged executable also runs the original
translated initialization, creates all four workers, and verifies that two
execute to their sleep points. Release publication requires that self-test to
pass on Windows. The callback regression fixtures now use heap allocation to fit
the default MSVC host stack; Windows source CI also checks them.

The original USA ISO is required at every launch. Title-screen boot and gameplay
remain unverified. Retain `startup.log` when testing this development preview.
