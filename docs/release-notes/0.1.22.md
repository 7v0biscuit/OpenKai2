# v0.1.22

Reduce vector transform costs and preserve constant-register reads during dual
issue.

- Combine bounded operand validation, SIMD arithmetic and FMAC flag production
  for common add, subtract, multiply and product-sum instructions. Retain
  separate multiply/add rounding, instruction cycles and flag visibility.
  Boundary values, exceptional operands and uncertain cancellation keep the
  original calculation. NOPs avoid arithmetic setup.
- Ignore writes to VF00 before the paired lower instruction executes. Stores,
  moves and divisions now read the constant `(0, 0, 0, 1)` during the pair.
  Arithmetic targeting VF00 still updates flags. Add eighteen independent cases
  across both vector units and three upper/lower instruction families.
- Add 64 original register, cycle and memory snapshots for affine vertex
  transforms, including sliced execution, dense and sparse matrices, rotation
  and cancellation. Check every transformed position with an independent
  matrix product. The vector suite contains 51 cases.
- Verify the pinned upper-instruction source before applying the runtime
  overlay, keeping the public runtime class layout unchanged.

Three alternating Windows-binary runs under Wine measured 17–28% lower CPU cost
in sixteen vertex-transform workloads, with a median reduction of about 23%.
The product and selected-operand groups had median reductions of about 17% and
19%. The general control group improved by about 5% at the median, with three
cases roughly 3–9% slower. Output positions, state, cycle and packet hashes
matched. These synthetic costs do not establish retail game FPS.

The original USA ISO remains required at launch. Host audio remains disabled.
The constant-register correction needs retail validation for character poses.
Complete matches and sustained 60 game FPS remain unverified; window pacing
retains original guest timing.
